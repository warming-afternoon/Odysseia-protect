# 动态溯源部署与运维

## 数据流

普通资源继续直接返回 Discord 原附件 URL。只有资源的 `trace_enabled` 为真时，Bot 才会在用户明确确认后读取仓库源文件、生成个性化角色卡，并通过私有 R2 交付。

缓存键由用户 ID、资源 ID、源消息 ID 和密钥版本共同决定。同一用户在滑动 30 分钟内重复请求同一版本时，不会再次加密或上传；Bot 只重新签发 URL并把对象删除时间延长为“当前时间 + 30 分钟 + 5 分钟宽限”。

## 必需配置

1. 将 `.env.example` 中 `TRACEABILITY_ENABLED`、`ODYSSEIA_TRACE_*`、`TRACE_ADMIN_*`、`R2_*` 和 `REDIS_URL` 填写完整。
2. 使用以下命令生成 32 字节 Base64URL 密钥，并将输出安全保存：

   ```bash
   python -m src.traceability.watermark keygen
   ```

3. R2 桶必须保持私有。API Token 只授予目标桶的对象读写权限，不要公开 Access Key、Secret Key 或 AES 密钥。
4. 在 Cloudflare R2 控制台为同一桶配置两条对象生命周期规则：

   | 前缀 | 过期时间 | 用途 |
   | --- | ---: | --- |
   | `deliveries/` | 1 天 | Bot/Redis/清理任务故障时回收临时交付对象 |
   | `reports/` | 7 天 | 回收管理员核验报告 |

生命周期按天执行，不保证在精确时刻删除，也不控制下载权限。正常情况下，Bot 每分钟从 Redis Sorted Set 读取到期 Key，并用一次 `DeleteObjects` 批量删除最多 1000 个对象；不会扫描或列举 R2。签名 URL 独立在 30 分钟后失效。

## 部署顺序

```bash
docker compose build
docker compose --profile migrate run --rm odysseia-protect-migrate
docker compose up -d odysseia-protect-redis odysseia-protect
```

首次上线保持 `TRACEABILITY_ENABLED=false`。确认数据库迁移、Redis 健康、R2 权限和生命周期规则后，再改为 `true`，先为少量测试资源开启溯源。

## 管理员核验

`/溯源 核验` 直接打开 Modal。File Upload 一次接受 1～10 个附件，每个附件独立产生 `TR-...` 任务号、中文 Markdown 报告和技术 JSON 报告。即时响应会附上两份文件；R2 则保存包含两份报告的 ZIP。

- 支持：PNG、JSON、ZIP、7z。
- 只有不超过 25 MiB 的角色卡可以在上传时开启动态溯源；关闭溯源的受保护资源不受此限制。
- 不支持：带密码或加密压缩包、嵌套压缩包、符号链接和不安全路径。
- 限制：最多 1000 项、解压总量 3 GiB、单项默认 50 MiB（与 `TRACE_MAX_OUTPUT_BYTES` 一致）、压缩比不超过 100:1。
- 非 PNG / JSON 项会写入报告为 `skipped`，不会导致整个压缩包失败。
- 正常完成会立即发送 Ephemeral 报告；原 interaction 过期后使用 `/溯源 报告 report_id` 获取。
- 技术 JSON 使用 `downloader_discord_user_id` 表示下载者；水印内部继续使用兼容字段 `uid`。
- 报告只提供调查证据，不执行自动封禁或处罚。

## 监控建议

- `deliveries/` 临时占用超过 5 GB；
- 最老临时对象超过 2 小时；
- Redis ping 失败；
- R2 上传、签名或批量删除连续失败；
- 核验任务长期停留在 `queued` 或 `processing`。

Redis 故障时会退化为单进程缓存；R2 故障时直接下载会尝试退化为 Discord Ephemeral 个性化附件，文件须符合当前交互的附件大小限制，超限则记录交付失败。进程崩溃后遗留的 R2 对象最终由 1 天生命周期回收。

## 新版载体与兼容边界

新副本不再写入 `extensions.odysseia_trace`。重新签发时会移除旧的该扩展，其他扩展保持原样；旧副本仍可通过兼容读取核验。

PNG 保留 `trAc`，并在安全条件允许时选择 `mes_example`、`personality`、`scenario` 中一个字段插入 `{{//随机标签:Base64URL凭证}}` 注释。标签是每次签发生成的 16 位小写十六进制随机字符串，同一次签发的 `chara`、`ccv3` 和已有顶层镜像共用标签。不会使用 `description`，不会添加新换行，不会创建缺失字段、改写非字符串字段或强行纠正冲突镜像。所有候选不安全时 PNG 仅保留结构层；JSON 无其他载体可用，会拒绝签发。跳过原因与载体清单在加密载荷中记录。

注释外部没有品牌名或固定版本前缀；内部信封保留 `v`，先解码读取版本，再进行加密认证。未知版本会明确报告不支持，未来兼容旧版本需要保留对应解析器和密钥。随机标签无需数据库记录，也不作为身份认证依据。扫描和重新签发清理使用同一识别规则；只有结构完整的信封才被清理，损坏候选保留原文并记录核验失败。普通注释保持原样，其中符合 `{{//16位小写十六进制标签:...}}` 形状的注释属于候选。每份 JSON（含顶层镜像）最多 128 个候选，单个编码凭证最多 32 KiB，超限会明确拒绝。尚未正式部署的旧品牌注释不再识别或专门清理，测试样本应从原始卡重新签发；正式服旧 `extensions.odysseia_trace` 扩展仍保留兼容。随机标签只降低直接辨识度，批量删除注释仍能移除这一层。

**默认空字段优先。** `TRACE_MACRO_ALLOW_EMPTY_FIELDS=true`（默认）时，从所有空候选中随机选一个；没有空候选时才选择安全非空候选。设为 `false` 时只选安全非空候选。已验证 SillyTavern 1.14、1.18、1.19 默认群聊为 SWAP，拼接前后缀为空。手动选择 JOIN 且前后缀为空时，空 personality/scenario 不增加标题，空 mes_example 会增加 `<START>\n`。只有配置自定义前后缀（例如 `[<FIELDNAME>]`）时，才可能多出 `[Personality]` 等包装，进而触发提示词模板已有标题。因此不能承诺空字段注释在所有路径下不改变提示词。含宏或模板的字段会被跳过，尤其不能在含 `{{pick}}` 的同一输入中添加注释，因为它会影响确定性随机种子。非空字段插入点在尾部空白之前，避免改变 trim 行为。

兼容性测试执行了上游真实宏引擎与提示词相关函数，但不是完整浏览器导入、导出及实际 API 请求抓包。版本、提交、复现命令、原始比较结果及未覆盖配置见 [`tests/compatibility/README.md`](../tests/compatibility/README.md)。扩展、自定义模板、第三方客户端仍需实际验证，不能以注释最终消失代替全提示词兼容性检查。

独立 JSON 可开启动态溯源、交付和核验，PNG 中导出的 JSON 也可单独核验。R2 对 JSON 使用 `.json` 和 `application/json`；ZIP/7z 中的 JSON 与 PNG 均会处理。JSON 字段、格式或内容经过编辑后，只要仍有可认证凭证，就按凭证命中统计，不核对正文内容。

## 可选像素层

`TRACE_LSB_ENABLED=true` 为默认值，未配置时也会开启，可显式设为 `false` 关闭。像素层仅用于 PNG，JSON 继续使用注释宏载体。使用原有 V2 密钥散布 RGB LSB 协议，重复次数固定为 3，与结构层使用同一个自包含加密凭证。已有 RGB8/RGBA8 路径保持协议兼容，不引入并发锁或串行队列。管理员核验即使未开启新签发的像素层，也会尝试读取已有 V2 像素层。

- 静态调色板、灰度、交错 PNG 及 `tRNS` 透明色按需转为非交错 RGB8/RGBA8，再写入像素水印；保留宽高、显示颜色及 Alpha。只进行一次图像解码和一次 PNG 编码，不中间另存图像。
- 源文件上传仍至多 25 MiB。交付输出、独立核验、像素提取及 ZIP/7z 单成员默认至多 **50 MiB**，使用 `TRACE_MAX_OUTPUT_BYTES=52428800` 配置。
- 图片至多 800 万像素；解码及转换后的单份像素缓冲区至多 **50 MB（50,000,000 字节）**，在解码前按位深和实际通道数预检。该限制不代表整个进程的内存峰值，输入、输出和临时缓冲仍占用额外内存。载荷至多 8192 字节。
- 动画 PNG 和 16 位 PNG 保留原图像编码，不转换、不写 LSB。容量不足、处理预算耗尽、像素或内存预算超限、输出超限，以及无法安全转换灰度色彩配置等已知情况，也从原始源文件重新签发无 LSB 副本，不交付半转换结果。
- 降级交付不额外提示普通下载者。加密载荷中的 `pixel_layer` 记录 `skipped` 及原因，`carriers` 不再声明像素层；管理员报告显示“LSB 像素层：未写入”及原因。主动跳过不会被误报为签发后缺失，损坏文件和未知异常仍停止交付。
- `chara`、`ccv3`、有效 `trAc` 和其他可保留元数据原字节保留；转换时同步调整 `bKGD`、`sBIT`，展开并移除 `PLTE`、`tRNS`，移除失效的 `hIST` 和签名。灰度 ICC/cICP 配置不能直接沿用于 RGB，遇到此类配置保留原图并跳过 LSB。
- 为避免重新签发后遗留旧密钥像素凭证，写入前清除整张图的 RGB 最低位，再按稳定散布协议写入新数据。相对转换后的参考图，每个 RGB 通道最多变化 1，Alpha 不变；IDAT 会重新编码，文件体积可能增加。
- 元数据被删除、PNG 无损重编码且像素不变时仍可提取；**不能保证缩放、裁剪、截图、重绘、有损压缩或社交平台转码后恢复**。
- 同一次提取至多尝试 8 个密钥，共用 10 秒协作式预算。Pillow 的原生解码/编码调用无法在调用中途被该预算打断，另有输入和像素上限约束资源消耗。
- `Watermark/lsb_watermark.py` 的实验 V1 只在底层显式 `legacy_v1=True` 时读取，不自动降级；生产核验支持 V2。V1 的 CRC 只校验损坏，最终身份信息仍必须通过加密信封认证。

关闭或跳过像素层时，如果源文件可提取到已知密钥的旧像素凭证，或源文件中的有效凭证声明已有像素层，会拒绝保留旧像素重新签发，避免新旧身份冲突。未知退役密钥不可检测，因此仍应使用原始无水印源文件。签发策略和输出大小配置进入缓存键，部署新策略后不会命中旧交付缓存。

## 密钥轮换与核验解释

`ODYSSEIA_TRACE_KEY_ID` 和 `ODYSSEIA_TRACE_KEY` 只决定新副本使用的当前密钥。可将旧密钥放入 `ODYSSEIA_TRACE_VERIFY_KEYS` JSON 对象：键是原 key ID，值是对应 Base64URL 密钥。当前密钥加历史密钥最多 8 个版本。不要在聊天、日志或仓库中保存真实密钥，也不要重复使用 key ID 表示不同密钥。删除历史密钥后不能再解密对应旧副本。

签发策略版本、当前 key ID 和像素/空字段配置进入交付缓存键，升级后不会命中旧扩展方案的缓存。

各层独立提取与认证。损坏层不会掩盖其他有效层，报告列出每层结果；多个可认证载荷相互冲突时拒绝给出单一命中。核验只认证签发凭证，不判断当前角色卡正文是否属于对应资源，也不能检测同资源副本之间的凭证移植。认证成功即计入命中，内容状态统一为 `not_checked`，报告明确显示“未检查卡片内容，仅认证签发凭证”，不宣称内容匹配。

新签发凭证保留下载者 ID、作品/帖子 ID、资源版本 ID、已知的原作者 ID、签发时间和随机交付 ID，不再计算或写入 `content_sha256`、`content_digest_version`。作者 ID 来自资源记录，未知时为空；签发时间是副本生成时间，同一缓存副本的重复下载沿用原签发时间。旧版带摘要凭证和早期扩展凭证继续认证，默认核验不检查其中的正文摘要。签发缓存策略已更新，部署后新下载不会复用旧策略缓存；旧副本无需重新下载即可按新规则核验。

服务 API 和命令行可传入外部可信的作品 ID、资源 ID。为兼容旧调用，仍保留显式可信内容摘要参数，但只检查旧凭证中已签署的摘要是否与传入值一致，不计算当前正文摘要；新凭证没有内容摘要，显式传入该参数会拒绝核验。不要把从同一嫌疑样本中提取的值当作外部可信输入。管理员默认批量核验没有外部参照，会标记 `context_status=not_provided`。内容摘要、账号字段或有效加密凭证都**不能单独证明传播路径、账号本人行为或泄露责任**；本系统不自动处罚。
